# 第 0 章：怎样把学习变成研究证据

## 这一章的目的

你不需要一开始就“看懂论文的每个公式”。研究阅读的正确起点是：能说清作者想解决什么、如何声称解决、证据在哪、自己还不懂什么。术语不懂不是失败；没有记录地跳来跳去才会让学习失去积累。

## 一篇论文的四遍阅读

### 第 1 遍：定位（约 20 分钟）

读标题、摘要、图 1、引言最后两段、结论、表格标题。写下：

- 旧方法的具体瓶颈是什么？是 `O(T^2)`、HBM、KV cache、还是精度/训练？
- 方法属于 ALG、KER、SYS 中哪些？
- 它最重要的主张是什么？作者用哪张图/表支撑？
- 有哪些前置名词不懂？只列出来，不当场全部解决。

### 第 2 遍：机制

读核心公式、算法框、关键图。尝试自己画 dataflow：输入是什么、改变了什么、输出是什么、哪一步节省了代价。遇到维度时写形状，而不是只抄符号。

### 第 3 遍：实现与证据

读 implementation、appendix、实验设置。问：GPU/精度/序列长度/模型规模是什么？baseline 是否公平？包含 selection、preprocess、KV cache 了吗？

### 第 4 遍：可复现问题

只在前 3 遍后进入代码。先选择一个最小主张，写复现卡。此时你应该知道自己为什么运行某个脚本、结果该和谁比、失败意味着什么。

## 报告的最小写作循环

每读完一个关卡，不要写很长的综述，先完成下面四句：

1. **背景：** 以前的做法在什么场景遇到什么成本？
2. **方法：** 这类方法改动哪一部分计算？
3. **代价：** 它把成本转移到了哪里，或牺牲了什么？
4. **证据：** 在什么硬件、形状、模型和指标下，作者观察到什么？

这四句会逐步成为最终报告的段落。不能回答的地方标成 `TODO(question)`，而不是用含糊的形容词填满它。

## 研究中的“问题清单”

建议在每篇论文笔记末尾保留三类问题：

- **概念问题：** 例如“online softmax 的重缩放为什么不改变结果？”
- **证据问题：** 例如“作者没有计 mask construction，这对总速度影响多大？”
- **研究问题：** 例如“在我的 A100 上，block size 是否改变 Native Sparse Attention 的最优点？”

前两类靠学习和复现回答；第三类才可能成为你的后续课题。
