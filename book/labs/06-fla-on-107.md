# Lab 6：在 107 上做 FLA 的最小 smoke test

## 目标

不是立即复现整张 FLA 性能表，而是确认你能从 FLA 的测试/算子/benchmark 中抽出一个可控实验。

## 固定两个仓库 commit

本地教程代码与远程 FLA 是两个 Git 仓库。不要在远程 `main` 上临时改教程；按附录的方法从
已推送分支建立独立 worktree。进入教程 worktree 后先记录：

```bash
git rev-parse HEAD
git -C ~/sparse_linear/flash-linear-attention rev-parse HEAD
```

本教程初次核对 FLA API 时使用的 FLA commit 是
`d1ce07369d581813553f30a750af3b6b5f9af6a9`。以后更新可以，但实验卡必须写新 commit。

## 三个 Slurm job 的顺序

所有命令都从远程教程 worktree 根目录运行；Slurm 在启动程序前就要打开日志，所以先创建
`artifacts/`：

```bash
mkdir -p artifacts
sbatch cluster/discover-gpu.sbatch
```

读完 discovery 输出的 GPU 与 driver 后，才选择 PyTorch wheel。若节点是当前 driver 可支持
的 A100/RTX 5090，可从 PyTorch 官方安装页选择对应 CUDA index；例如确认使用 CUDA 12.8
wheel 后：

```bash
sbatch --export=ALL,TORCH_INDEX_URL=https://download.pytorch.org/whl/cu128 cluster/setup-env.sbatch
```

setup job 会调用 `~/miniconda3/bin/conda`，在
`~/sparse_linear/.envs/sla-tutorial-py312` 创建独立 Python 3.12 prefix，安装
PyTorch/Triton/FLA，并保存 `pip freeze`。它不会使用 Miniconda base 的 Python 3.14，也
不会向系统目录写入。

!!! note "为什么这里不用系统 Python venv"
    107 的 `/usr/bin/python3.12` 存在，但当前节点缺少 `ensurepip/python3.12-venv`；
    `python3.12 -m venv --help` 能显示帮助，不代表真的能创建环境。首次 setup job `26147`
    正是因此失败。无 root 权限时，用已有 Conda 创建指定 Python 版本更可靠。随后 job
    `26148` 发现默认 Anaconda channels 要求非交互接受 ToS；课程脚本不替用户接受条款，
    而是用 `--override-channels -c conda-forge` 只安装 Python/pip，再从 PyTorch 官方源安装
    CUDA wheel。

    job `26150` 已创建 prefix，但 pip 在把数 GB CUDA 包安装到 NFS 环境时出现一次
    `OSError: [Errno 2]`。home 总空间充足，问题更像 NFS cache/tmp 的瞬时可见性。因此脚本
    在 `cd .` 刷新后，将 `TMPDIR` 与 pip cache 指向计算节点本地
    `/tmp/sla-$USER-$SLURM_JOB_ID`；环境本身仍持久化在 home，wheel/cache 不进入 Git。

环境成功后提交：

```bash
sbatch cluster/slurm-smoke.sbatch
sbatch cluster/fla-smoke.sbatch
```

第一个作业跑课程 reference、Triton vector add 与 dense prefill/decode benchmark；第二个作业
固定小 shape，比较 FLA naive GDN、fused recurrent GDN 与 scalarized fused KDA 的 output 和
final state。

## 源码阅读顺序

1. `naive.py`：先对照递推与 tensor layout；
2. `fused_recurrent.py`：确认 decode 路径、state layout 与输入 gate；
3. `chunk.py`：再追训练/prefill 的块内算法；
4. tests/benchmarks：核对作者使用的 shape、dtype、forward/backward 与容差。

## 已观察到的 FLA 路径

```text
GDN: fla/ops/gated_delta_rule/{naive.py, chunk.py, fused_recurrent.py}
KDA: fla/ops/kda/{naive.py, chunk.py, fused_recurrent.py}
```

GDN 有公开 naive reference；KDA 当前公开目录以 fused/chunk 为主。课程 probe 用 scalar gate
将 KDA 与 GDN naive 对齐，这正好验证第 12 章的包含关系。第 13 章会把这条路径与 layer 和
cache 串起来。

## 通过条件

你能给出两个 commit、job id、GPU、环境 lock 和 operator JSON；能指出 probe 使用的是哪
一个实现、比较了 output 还是 state，以及它是数值证据而不是性能/模型质量证据。
